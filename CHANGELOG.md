# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow
[Semantic Versioning](https://semver.org/) (0.x: minor releases may change behaviour).

## [Unreleased]

### Fixed

- Deploy helper follow-ups to PR #61 (PTC-82): an idempotent MCP `revert` clears a stale `reverting` marker from the receipt; Pages `prune` never removes the newest `<api>-pages-reverted-<digits>` container (the evidence and restart policy a killed revert needs to recover) and skips a container that vanishes between its listing and inspect; a failed Pages build redacts the repository path and any `lookup <host>` DNS host from the stderr tail; a rollback failure is reported on stderr before a deferred SIGTERM exits 143, and the Pages apply restart of the live API after a failed retire is held against SIGTERM too. Real-process tests cover SIGTERM during a failure-triggered Pages rollback. Not changed: the few bytecodes between entering an `except` and `hold_sigterm()` cannot be closed in Python without blocking SIGTERM during the whole health wait, and docker children keep the blocked mask during a rollback on purpose.
- Pages `apply`: when the rollback after a failed swap itself fails (the rename back or the start), it now calls `recover_original` instead of leaving the original API stopped under the backup name, and raises the original error with the recovery error as its context. The rollback never starts a Pages-labelled container, or one it cannot inspect, under the API name. When recovery cannot finish, it may leave the API stopped and prints `Rollback incomplete: ...` naming where each container is; run `apply` again to reconcile (PTC-88).
- Pages `apply` holds SIGTERM across the retire (stop, rename to the backup name, policy update) and merges the two rollback blocks into one that knows whether the rename happened, so a SIGTERM right after the rename restores the original API instead of leaving it stopped under the backup name; a failure before the rename still just starts the API again (PTC-89).
- Pages deploy digest now covers the backend source, the `replacement` create-body function and the Dockerfile, not only `pages_backend.py`, so a change to either re-applies instead of reporting already applied. `check` prints the digest. The digest, and so the image tag and label, changes for every host: `owner:plane-pages:check` reports a source difference until you redeploy. Direct route: revert, then apply. Saltbox route (see "Saltbox route" in `docs/extensions.md`): run `mise run owner:plane-pages:build`, update `plane_role_api_docker_image` in the inventory and the `plane-toolchain.pages.source` label in `plane_role_api_docker_labels_custom`, run `sb install mod-plane`, then run `mise run owner:plane-pages:check` (PTC-90).
- Pages deploy validates the API container and worker names strictly (`[A-Za-z0-9][A-Za-z0-9_.-]*`) in `main` and again in the remote program, so a leading dash such as `--help` or a Unicode name is refused, and URL-encodes the name in the container create request (PTC-101).
- Workspace rename (PTC-82): the orphan sweep ignores read-only `check` snippets (now marked `check:<token>`) instead of refusing or killing them, and an old-format marker makes it refuse with the pid and the kill command instead of an unexplained refusal. The API-container clash check also compares container ids, not only names. `check` probes that `EmailNotificationLog` has no workspace column.
- MCP apply and revert no longer refuse a host entry point whose receipt is stale but whose content is exactly a `ce_tools.py` shipped in a past release (for example after another deploy wrote `server.py` without updating the receipt). Foreign content is still refused; `check` is unchanged. Releases append their digest to `RELEASED_ENTRY_POINT_DIGESTS`.
- Workspace rename (PTC-91): an own-host URL to the old workspace followed by whitespace or prose punctuation (`https://host/acme, see`, `(https://host/acme)`) is now rewritten, and `check` reports it when it will not be. The slug must still not be followed by a slug character, so `acme-two` never matches `acme`, and a dot ends the slug only when no slug character follows it, so own-host file names such as `/acme.png` are left alone.
- Workspace rename (PTC-95): a snippet that crashes before its summary (an import error, say) now fails with its exit code, the exception class and a redacted stderr tail (`check gave no summary (exited with code 1: ModuleNotFoundError; stderr: ...)`) instead of only `gave no summary`. Snippet stderr is captured to a temporary file instead of discarded; non-JSON stdout is still never shown.
- Workspace rename (PTC-93): `check` counts the Description rows the slug step rewrites without Live whose stored `description_binary` keeps the old slug, lists them by id (`Not rebuilt: N in descriptions.description_binary`) and refuses, as does apply, unless `PLANE_RENAME_ALLOW_STALE_BINARIES=1` accepts them. The `rebuild` count no longer includes Description rows, and the slug step's `not_rebuilt` no longer counts comments (they have no binary in Plane CE v1.4.3) or rows with no stored binary.
- Workspace rename (PTC-94): the snippet now waits for the host to acknowledge each journal line on stdin, sent only after the line is fsynced, before the write it covers, so a killed host program can no longer leave a rewritten row without a journal entry (the documented known risk is closed). The snippet runs as `manage.py shell -c <bootstrap>`, which reads a length-prefixed program from stdin and keeps stdin open for the acknowledgements. The row step journals the same single read of each row that it rewrites, instead of a second query.
- Deploy helpers and workspace rename (PTC-96): every Docker CLI call has a timeout (`docker()` and `docker_ok()` default to 5 minutes, `docker build` to 30), and expiry raises `docker <command> timed out after <n> s` without container names, so the usual rollback runs. `docker_ok()` raises on expiry too instead of returning False, so a hung `inspect` never reads as a missing container. Pages health retries a hung probe within its budget, and a hung probe in an apply rollback, `recover_original` or the revert recovery (`restore_any`) starts nothing more, inspects the API name once more and stops it (best effort) unless it holds the unlabelled original, and reports `Rollback incomplete` with where the derived container may be (including a `-pages-failed-` name it was being moved to), then the original error is raised. `run_remote` limits the SSH session to 6 hours (exit 124 with the interrupted guidance). The rename's streamed `pg_dump` and `pg_restore` read-back have 2 hour deadlines and the database size query 2 minutes. `docker()` and `run_remote` keep their signatures; `timeout=` overrides the default.

## [0.3.1] - 2026-11-14

### Fixed

- Pages revert: a revert killed after the original was renamed back to `api` but before it started left `api` stopped, and a repeat revert reported "already restored" without starting it. A repeat revert now starts the stopped original, restoring the live restart policy, when a `<api>-pages-reverted-<digits>` container shows the revert was interrupted; a stopped `api` without one is still left alone as stopped on purpose (found by the new kill-injection harness; PTC-80).

### Tests

- Pytest warnings are errors (`filterwarnings = ["error"]`); a coverage floor of 81% is enforced in `mise run check` and CI; a kill-injection harness runs Pages apply and revert killed before and after every docker call (and failed at every call) and proves the next run converges (PTC-80).

### Changed

- Workspace rename: apply and revert share one state machine (`run_context` plus `run_*` helpers and `run_steps`, which runs each step as effect, then advance, and hands failures to the operation's own recovery), so the snippet call, service stop and start, preflight, refusal wrapping, failure reason, drain-gate and warning messages exist once. No behaviour or message change. The `check` plan scan streams rows with `iterator()` like the unfixed scan (PTC-64).
- Python floor raised to 3.12 (`requires-python = ">=3.12"`); only 3.12 is tested (PTC-81).

### Documentation

- ADR 0001 Status now reads "Accepted; partly superseded by Removal (PTC-30)", and its read-both Migration policy, Deprecation window and Agent rule sections carry a historical banner (PTC-81).
- `docs/configuration.md` lists config file locations per context (checkout, installed project, worktree) and records `.deploy/env` as a legacy fallback used only when `config/local.env` is absent; no behaviour change (PTC-81).

## [0.3.0] - 2026-11-14

### Fixed

- Workspace rename: appending to `records.jsonl` after a kill that left a torn final line first repairs the tail (adds the missing newline to a whole record, or truncates a partial one back to the last newline, fsynced), so the new record is no longer glued onto it and lost or refused as a corrupt line (PTC-58).
- Workspace rename: apply and revert take an exclusive `flock` on `run.lock` (0600, private-file checked) in the receipt directory for the whole run and refuse before any stop when another run holds it; `check` takes none (PTC-59).
- Workspace rename: the backup step checks free space in the receipt directory first, then runs `pg_restore -f /dev/null` on the finished dump (every data block read, nothing written) inside the database container and refuses (before any data change, leaving no dump file) if it does not list; `pg_dump` and `pg_restore` failures now carry a bounded stderr tail with quoted values redacted (PTC-61).
- Workspace rename: each Django snippet runs with a per-run `PLANE_RENAME_RUN` marker and an idle deadline (15 minutes without output, restarted on each line). After any abort, timeout or non-zero exit the tool stops the marked process inside the API container (SIGTERM, then SIGKILL, found through `/proc`) and confirms it is gone before services are restarted or the receipt reset; when that cannot be confirmed, services stay as they are and the message says so. Apply and revert first stop any snippet orphaned by an earlier killed run (PTC-60).
- Workspace rename: `check` first probes the Plane CE model assumptions read-only through Django's `_meta` (table names, the unfiltered manager, every field the snippet uses, `workspace_id` on owned models, JSON columns being `jsonb`, binary columns being binary) and refuses on any mismatch, printing each by model and field; apply refuses with it. Also available as the `probe` operation. Not yet run against a real Plane v1.4.3 (PTC-62).
- Workspace rename (review fixes to the above): a revert with no receipt refuses before any Docker call; the drain gate fails fast, with accurate wording, when the workers are already stopped; snippet markers carry a receipt-directory id so a sweep never kills another directory's live run (it refuses instead); `check` scans emit `progress` events and `PLANE_RENAME_SNIPPET_IDLE_SECONDS` sets the idle deadline; stderr tails hide container names; the kill script's wait is bounded; an interrupt with an unconfirmed stop warns on stderr (PTC-59, PTC-60, PTC-61, PTC-63).
- Workspace rename: a queue still not drained after 60 s now refuses (before the slug change: services restart and the receipt returns to `pending`) instead of warning, unless `PLANE_RENAME_ALLOW_UNDRAINED=1` is set; an API container that is also a service container is refused before SSH and on the host; a run on an already complete rename re-runs the health check and says how to archive the receipt directory, and a receipt for a different rename (for example the opposite one) says the same (PTC-63).
- MCP deploy writes the backup atomically (temporary file, fsync, `os.replace`, directory fsync, entry-point mode) before it touches `server.py`. `server.py` is still written in place so the bind-mounted inode survives, but a kill mid-write now recovers: an empty file or a prefix of the new bytes (receipt pending) or of the backup is accepted by `apply` and `revert`, which carry on from the backup, and a failed recovery rolls back to the backup. Foreign content is still refused. The backup-prefix rule needs a `pending` receipt or the new `reverting` marker that revert writes before its rewrite (a final receipt with a shortened `server.py` is refused). Receipt files are now created 0600 (they were 0644). Kill-injection tests cover each write step (PTC-65).
- The Pages and MCP remote programs install a SIGTERM handler (`remote.guarded`): SIGTERM raises `SystemExit(143)` so the existing `BaseException` rollbacks restore the container swap or the entry-point bytes and receipt, prints one line, and later SIGTERMs are ignored. SIGTERM is also blocked (`pthread_sigmask`) during every failure-triggered rollback and delivered once it finishes, so it cannot abort one. Real-process tests send SIGTERM during Pages apply and MCP apply (PTC-66).
- Pages deploy diagnostics and housekeeping: container creation has a socket timeout, always closes the connection and names the HTTP status or error kind; derive and build share one `build_image` helper that keeps stdout quiet and reports the exit code and a bounded stderr tail when the build fails; apply and revert results list retained container names; `owner:plane-pages:prune` lists, and with `PLANE_PAGES_PRUNE=yes` removes, stopped labelled `-pages-reverted-<n>` and `-pages-failed-<n>` derived containers (never the live API, the rollback container, an `-aside` or unlabelled container, or a running one); build failures hide the base image reference; health probes time out after 20 seconds; apply reminds to revert before Compose updates; a failed restart-policy update warns on stderr; the health wait stops after 120 seconds as well as 45 attempts (PTC-68).
- Pages deploy and Docker Compose, documented decision (PTC-67): checked on a scratch Compose project that `docker compose up` removes the derived container and starts the retained original (Pages lost), and `down` removes the retained original. Labels are immutable, so the retained original cannot lose its `com.docker.compose.*` labels; the derived container keeps them too, which makes `up` converge on one container instead of two. `docs/extensions.md` says to revert before Compose updates; tests pin the label sets of the original, derived and retired containers.
- `install_project.py label` refuses HTTP redirects, so the Plane API key is never sent to another host or over plain http; it reports the redirect and asks for the final `PLANE_API_URL` (PTC-72).
- `install_project.py apply` writes a pending receipt first, then the files, then the final receipt. If a write fails midway, `revert` undoes exactly what was written (files still as before are skipped; edited ones are refused) and a repeat `apply` finishes the install. `label` refuses an interrupted installation. The pending receipt marks each file done as it is written, so a file apply never reached stays the user's even if they edit it before revert or the repeat apply. Earlier receipts still revert (PTC-73).
- The installer reads and writes target files as UTF-8 with line endings untouched: a CRLF `AGENTS.md`, `CLAUDE.md` or Codex config gets its block appended in CRLF and reverts byte for byte, and non-ASCII JSON stays unescaped. Invalid UTF-8, a non-object `mcpServers` or `hooks` and a non-list `SessionStart` are refused with a message instead of a traceback, `main` reports any other failure on one line, and a symlinked `CLAUDE.md` or `AGENTS.md` gets a message that says how to fix the layout (PTC-74).
- `install_project.py apply --no-preapprove` installs without adding `plane` to `enabledMcpjsonServers`. The receipt records `approval` (`added`, `listed` or `declined`) for `.claude/settings.json`, and `docs/project-install.md` explains that a committed pre-approval plus the shim runs repository-controlled shell without a prompt (PTC-75).
- The bridge (`scripts/plane-mcp.sh`) stops with a clear message when sops fails to decrypt, refuses a symlinked secrets file, requires the installed `mcp-remote` (local or reused from the main checkout) to match the version in `package-lock.json`, and says so on stderr when git is older than 2.31 and the worktree fallback cannot work. The installed shim strips a pair of quotes and a trailing comment around `PLANE_TOOLCHAIN`; the previous shim stays accepted by revert and is reported as outdated. The zsh prompt caches its status and runs python3 only when its inputs change or after 30 seconds (PTC-76).
- CLI readback is stronger: `task update` compares the normalised body text instead of only checking it is non-empty, `page create` also checks the access level and a non-empty body, and a task identifier whose project differs from an explicit `--project` is a usage error (exit 2) instead of silently overriding it (PTC-77).
- Release and workflow supply chain: the release workflow now requires a successful `check` run on the tagged commit before `gh release create`, and `GH_TOKEN` is scoped to the two steps that use it (with `checks: read` added to the job). The example workflows install uv with `pip install --require-hashes` from `examples/github/uv-requirements.txt` instead of an unhashed version pin. CI runs on `ubuntu-24.04` and asserts the zsh major version it installs (PTC-78).
- The GitHub examples installer refuses a symlink anywhere under `.github` or `.agent-state` (not only the last component), writes files through a temporary file, records the receipt first so an interrupted apply can be completed or reverted, and reports examples that are older than this checkout instead of "already installed". `plane_event.py` completion checks for its own evidence comment and the target state before writing, so a retry after a partial failure no longer duplicates the comment (PTC-79).
- Review fixes for PTC-77..79: body readback compares HTML text nodes (a plain `a < b` no longer causes a false exit 5), installer temp files are created with `O_EXCL|O_NOFOLLOW` so a planted symlink cannot redirect writes, the release gate only counts `check` runs from GitHub Actions, and the release dry run is documented in `CONTRIBUTING.md`.
- Pages backend: a POST or PATCH body that is not a JSON object (list, null, string, number) now returns 400 "Request body must be a JSON object" instead of 500, and a Live conversion reply that is not a JSON object counts as a conversion failure (502, nothing written). The `pages_backend.py` payload digest changed: redeploy needed (`owner:plane-pages:revert`, then `apply`) (PTC-69).
- Pages backend: `ce_page` update no longer polls the database for 12 seconds after commit (it held a sync worker; a few concurrent updates could starve the API). It returns as soon as the write commits, with a `late_store_check` object (`seconds`, `html_sha256`, `compare`, `recheck_after`, `on_difference`) in the response. The async `ce_page` MCP tool waits `seconds` without blocking the event loop, retrieves the page, compares the body digest and returns `late_store: "unchanged"`, or fails naming the page id when a late Live store overwrote the update (replacing the API's 409). The `pages_backend.py` and `ce_tools.py` payload digests changed: redeploy needed (`owner:plane-pages` revert then apply, and `owner:plane-mcp-compat`) (PTC-70).
- Pages backend: tests now encode Plane CE v1.4.3's page permission rules (read from tag `v1.4.3`, `ProjectPagePermission` and the description update): non-owner access to a public page, another owner's private page hidden, guests without `guest_view_all_features` limited to own pages, and the permission-class contract guard. No behaviour change in `pages_backend.py`; `docs/extensions.md` states the permission model and that `ce_workitem_relation` list may return ids from other projects (kept unfiltered, each with its `project_id`). The `ce_tools.py` payload digest changed (docstring only): redeploy needed with the PTC-70 redeploy (PTC-71).

## [0.2.1] - 2026-11-14

### Fixed

- `mcp_deploy`, `pages_deploy` and `workspace_rename` no longer print a local traceback when the remote program fails: the SSH `user@host` and the whole remote program source stayed out of the `CalledProcessError` argv dump. ## [0.2.0] - 2026-11-14

### Added

- Apply pre-approves the `plane` MCP server by adding it to `enabledMcpjsonServers` in the target's `.claude/settings.json` (created if absent, other keys kept), so Claude connects without an approval prompt. Revert removes the entry only when apply added it, keeps every other edit to the file, and leaves an already-listed `plane` alone. Apply refuses invalid JSON or a non-list value without writing. Receipts from before this change still revert. Repeating apply on an older installation names the outdated shim or missing pre-approval and changes nothing; revert, then apply again to update it (PTC-55, PTC-56).
- `plane` command-line interface over the Plane MCP server (`mise run plane:cli`, `python -m plane_toolchain.cli`): `task list`, `task show`, `task update`, `comment list`, `comment add`, `page list`, `page show`, `page create`, `relation list` and `relation add` print JSON (writes are verified by readback; no Page editing, relation deletion or retries; see `docs/cli.md`), `--project` overrides `PLANE_PROJECT`, and exit codes separate usage (2), configuration (3), MCP failure (4), readback mismatch (5) and interrupt (130). The API key is read from the environment only and never printed. `connection()` accepts an optional environment (PTC-2).
- Workspace slug rename owner runbook, `docs/workspace-rename.md`: prerequisites and environment, the unverified Plane CE v1.4.3 assumptions to check before a live run, `check` refusals, the cache flush dry run, apply states with resume-or-revert guidance per failure, revert and partial restore, known risks, the manual `pg_restore` last resort and the post-run steps. Linked from the README and `docs/extensions.md`; a docs test checks that it names every environment variable and owner task (PTC-42).
- `owner:plane-workspace-rename:check`, `:apply` and `:revert` tasks (`python -m plane_toolchain.workspace_rename`). Slugs and destination come from the environment (`PLANE_RENAME_FROM`, `PLANE_RENAME_TO`, `PLANE_MCP_SSH`, `PLANE_API_CONTAINER`, `PLANE_LIVE_URL`, optional receipt directory, `PLANE_API_URL` and service overrides), are validated before SSH and never printed. The payload and snippet travel on stdin, never in argv, and the remote exit code passes through (PTC-41).
- Installed projects used from a linked git worktree read the main checkout's git-ignored `.plane/local.env` (merged per key, the worktree's own file wins) and `.plane/plane.enc.env`, in place and never copied. The shim also finds `PLANE_TOOLCHAIN` there. The bridge reuses the main checkout's `mcp-remote` only when `tools/mcp-remote/package-lock.json` has the same SHA-256 in both and the bin stays inside the main `node_modules`; otherwise it fails with the `mise run setup` hint. Symlinked main files and a common dir not named `.git` get no fallback. Installs made before this keep working: revert accepts the earlier shim, and repeat apply reports it as outdated without rewriting it (PTC-47).
- `owner:project:label` ensures the `awaiting-decision` label exists in an installed project's Plane project over the REST API (key from the environment only, no network call when settings are missing or Plane is disabled), verifies it by rereading and records its id in the receipt. Installed `AGENTS.md` blocks gain the awaiting-decision rule. Revert never deletes the label. Installations from before this change keep their older block: revert restores them exactly, and apply and label report the block as outdated (PTC-52).
- The workspace rename Django snippet (`workspace_rename_backend.py`) has a read-only `check` that validates the slugs and reports every planned link rewrite per record and field, plus hits it will not fix, as JSON lines with ids, tables, columns and counts only (PTC-34).
- Agents flag a task blocked on a human decision with a comment holding the question and options plus the `awaiting-decision` label, and remove the label when answered (PTC-51).
- `owner:plane-pages:build` builds the derived Pages image from the upstream backend image (or `PLANE_BACKEND_IMAGE`) and prints its tag and source digest, without touching any container. Use it for Saltbox-managed hosts where the running API image is local (PTC-45).
- `ce_page` update replaces an existing Page body. It needs an `expected_updated_at` precondition and `force=true`, disconnects open Live editors first and keeps the old body as a page version (capped at 20). It refuses only if the body changed while editors closed, and reports a late Live overwrite with 409. Both server payloads changed; redeploy them (PTC-44).
- Workspace rename host operations: stop services (beat, queue drain up to 60 s without purging, worker, web, space, admin), restart Live, start in reverse order, and back up the database with `pg_dump` to an owner-only `backup.dump` whose SHA-256 is recorded in the receipt. Only `docker stop`, `start`, `restart` and `exec` are used. Library functions only; no task or CLI yet (PTC-38).
- Workspace rename apply state machine (`workspace_rename.deploy` and the host program `REMOTE`). `check` is read-only. `apply` runs every refusal before the first stop, then steps through `pending`, `stopped`, `backed_up`, `slug_done`, `rows_done`, `cache_done`, `started` and `complete`, each as effect then advance. Kills are resumable: a resume stops services again first and reuses a backup whose SHA-256 matches. If a service is running again before the slug change, the backup is set aside instead. A failure before the slug change restarts the services and resets the receipt to `pending`. It moves the backup and the journal aside under timestamped names (kept, and listed in the receipt), so the next apply takes a fresh dump and journals current originals. An unclear slug step is probed read-only before anything is decided. After the slug change, a failure stops with services down, for resume or revert. Known risk: a kill between the snippet printing a journal line and the host fsyncing it can leave a written row without a journal entry, and only the `pg_dump` backup recovers that row. No task or CLI yet (PTC-39).
- Workspace rename revert (`operation: revert` in the host program `REMOTE`) restores the slug and every journalled field from the receipt, from any partial or complete apply. It steps through `reverting`, `restored`, `started` and `reverted`, each as effect then advance, and a kill at any point is resumable by rerunning revert. Every refusal comes before the first stop: no receipt, a receipt for another rename, an unknown receipt state, a journal without a workspace record, an empty journal past the slug change, or an unclear slug state. The restore reads only the current `records.jsonl` and runs with services stopped. It is skipped when nothing was journalled, or when the slug change never committed. Then the cache is flushed, services start and health runs with the slugs swapped and the journalled workspace id. A partial restore prints every skipped row by id and restarts services, but it is not reported as complete: the receipt stays at `reverting` and the exit code is non-zero. The journal and `backup.dump` are kept; restoring the `pg_dump` backup stays a manual last resort. With nothing journalled, revert still probes the slugs read-only and refuses unless OLD is live and NEW is free. A partial restore restarts services even if recording it in the receipt fails. Apply and check now refuse after a finished revert (archive or move the receipt directory first), and refuse a journal or backup, current or rotated, that has no receipt. No task or CLI yet (PTC-40).
- Project installer (`scripts/install_project.py`, `owner:project:apply`/`revert`) that connects another project to the Plane MCP bridge, registers Codex and Claude session hooks, and adds an AGENTS.md block making Plane the authoritative task system (PTC-48).

### Removed

- **Breaking:** the Pages and MCP deploy helpers no longer read legacy `terrainlink` names, and the migration paths are gone. Pages `check`, `apply` and `revert` and MCP `check`, `apply` and `revert` refuse before any change (Pages `build` only creates an image and does not check) when they find `<api>-before-terrainlink-pages`, the `terrainlink.pages.source` container label on the API container or the backup, `server.py.before-terrainlink-ce`, `terrainlink-ce-receipt.json` or its `.tmp`. The message names what was found. The tripwire fails closed: a failed `docker ps` or `docker inspect` of a listed container refuses the run instead of reading as clean. To upgrade a host that has this state, first run the owner tasks at commit `1cb6153`: Pages `revert` (it consumes the legacy backup and parks the legacy derived container as an inert `<api>-pages-reverted-<ts>`; run `apply` there only if `check` passes there, since it refuses when the deployed digest differs) and MCP `apply` (MCP `revert` there does not migrate). Then run Pages `apply` with this release. Retired `-pages-reverted-*` containers keep the legacy label, are not checked and are left for owner cleanup. A Saltbox host's next build, from this release or the Saltbox role, must write the neutral label, or every operation from this release refuses there. Removed early by owner override of the ADR 0001 deprecation window; `legacy.py` is kept with the four refused names. Server payload digests are unchanged (PTC-30).

### Changed

- TerrainLink is removed from prose, comments and docs. The repository was extracted from TerrainLink under the MIT licence; the README line is dropped and the origin is recorded here, and `LICENSE` is unchanged. Legacy `terrainlink` names remain only as compatibility data in `src/plane_toolchain/legacy.py` and in the migration docs.
